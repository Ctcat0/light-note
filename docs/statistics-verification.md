# 固定资金渠道语义与统计分析验证记录

> 状态：本地实现和自动化验证已完成；真实 CloudBase 统计版部署与微信开发者工具人工验收待执行。

## 1. 阶段 A 审计结论

| 分类 | 审计结果 |
| --- | --- |
| 删除 | 错误的资金渠道资产核算应用层、维护用例、领域规则、刷新信号、维护契约与专用验证内容 |
| 修改 | 交易写入/响应、账户 DTO、用户初始化、错误码、个人页、金额工具、内存仓储与核心文档 |
| 保留 | `accounts` 集合、5 个默认固定渠道、两个分类型默认渠道、`transaction.accountId`、归属/存在/启用校验、名称图标展示 |
| 保留但改语义 | 内部 `accounts` 命名继续用于兼容；前端表单分别展示“支付方式”和“收款方式” |

阶段 A 自动化证明：

- 收入/支出新增、编辑、跨月编辑、逻辑删除、幂等、乐观锁和多用户隔离保持通过；
- 混合流水、单类型筛选、稳定复合游标、月度整月汇总和每日小计保持通过；
- 交易新增、编辑和删除后固定渠道文档逐字段不变；
- 正式 action 仅保留固定渠道查询和交易引用校验，不包含资产维护入口；
- 可选清理脚本默认 dry-run、要求指定用户、支持单渠道和分批，apply 还要求明确确认词。

## 2. 统计实现范围

- 月份选择与近 6/12 个月趋势选择；
- 月收入、月支出、月结余、收入笔数和支出笔数；
- 收入/支出月度趋势，跨年并补齐零值月份；
- 支出分类与收入分类金额、笔数、整数万分比和降序排行；
- 点击分类进入现有流水页，以年月、类型和分类 ID 下钻；
- 初始加载、刷新、空数据、初始错误、局部错误、重试和过期响应忽略；
- 刷新失败保留最近成功数据；交易变更信号触发统计页返回时刷新。

## 3. 数据与性能策略

统计复用 `ledger` 云函数三个只读 action。金额、笔数和分类分组在 CloudBase 聚合管道完成；前端只接收聚合结果，不下载整库交易。趋势对 6/12 个月分别执行受索引支持的月度聚合，当前不引入缓存集合。

分类名称采用当前记录关联语义。若历史交易引用的分类已物理删除，返回“已删除分类”与 `other` 图标并保留金额，避免统计合计丢失。分类下钻使用新增普通索引：

`ownerId ASC, type ASC, isDeleted ASC, categoryId ASC, occurredAt DESC, _id DESC`

页面使用原生文字和横向条形数据视图；所有条形旁都有金额文字，不新增图表组件、npm 依赖或分包。

## 4. 自动化场景

- 当前用户与其他用户数据隔离；逻辑删除记录排除；
- 空月份汇总、跨年趋势、零月份补齐和旧到新排序；
- 6/12 合法窗口与非法 `monthCount`；
- 分类排序、合计、笔数、占比和已删除分类兜底；
- 分类筛选游标绑定，跨分类游标拒绝；
- service 严格解析结余、趋势长度与分类合计；
- 原生条形宽度、占比格式和过期响应忽略；
- 既有收入、支出、分页、跨月和并发回归。

## 5. 真实环境待验收

1. 在开发环境创建分类下钻索引并等待可用；
2. 构建、上传并部署 `ledger`，重新编译小程序；
3. 核对当前月概览与现有流水月汇总一致；
4. 核对近 6/12 月跨年顺序和空月；
5. 核对收入/支出分类合计分别等于月收入/月支出；
6. 点击分类确认流水页显示对应月份、类型和分类筛选；
7. 新增、跨月编辑和删除收支后返回统计页，确认自动刷新；
8. 通过一次性调用代理分别制造趋势或分类失败，确认其他模块和旧数据保留；
9. 记录环境 ID 后四位、函数版本、requestId、时间和结果，不记录完整身份标识。
