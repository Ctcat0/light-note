# 收支流水 CloudBase 部署与真实环境验证

本文保留 2026-07-21 按单一收支类型查询流水的历史部署与验收记录。当前默认混合收支流水、收入闭环及新增索引请以 [`income-transaction-verification.md`](./income-transaction-verification.md) 为准。自动化测试不能证明 CloudBase 组合索引、真实 `OPENID`、云端聚合和开发者工具页面生命周期已经正常工作，以下步骤必须在开发环境人工执行。

## 1. 部署前操作

1. 在仓库根目录执行 `npm.cmd run check` 和 `npm.cmd run build:cloudfunctions`。
2. 打开 CloudBase 控制台，确认 `transactions`、`categories`、`accounts` 的数据权限均为“所有用户不可读写/仅管理端可读写”。不要开放客户端读写。
3. 保留唯一索引 `uq_transactions_owner_request`：`ownerId` 升序、`requestId` 升序、唯一。
4. 在 `transactions` 新建普通非唯一索引 `idx_transactions_owner_type_active_occurred_id`，字段严格按以下顺序：
   - `ownerId`：升序；
   - `type`：升序；
   - `isDeleted`：升序；
   - `occurredAt`：降序；
   - `_id`：降序。
5. 为批量展示关联创建普通非唯一索引：
   - `idx_categories_owner_id`：`ownerId` 升序、`_id` 升序；
   - `idx_accounts_owner_id`：`ownerId` 升序、`_id` 升序。
6. 等待索引状态变为可用。不要保留字段相同但缺少 `_id` 次级排序的重复交易索引。
7. 在微信开发者工具中右键 `cloudfunctions/ledger`，选择“上传并部署：云端安装依赖”。确认函数名 `ledger`、入口 `index.main`、超时 10 秒；本次无需新增环境变量。
8. 重新编译小程序，确认底部“记账”进入“账单流水”，且可进入“新增支出”。

如果第 4 或第 5 步控制台不允许 `_id` 参与组合索引，或运行时返回索引建议，不要改成 `skip` 分页，也不要声称部署成功；记录完整的脱敏错误码和控制台索引建议，回到代码与文档统一调整。

## 2. 场景一：同月多笔账单

使用同一开发账号创建三笔支出：

- 7 月 21 日 12.50 元；
- 7 月 21 日 23.00 元；
- 7 月 20 日 8.80 元。

返回流水页后验证：7 月 21 日只有一个日期组，当日小计 `¥35.50`；7 月 20 日小计 `¥8.80`；日期和组内时间均倒序；本月支出为 `¥44.30`。控制台对应记录均应为当前用户 `ownerId`、`type=expense`、`isDeleted=false`，金额分别为 `1250`、`2300`、`880`。

再创建两笔收入并切换到“收入”：7 月 21 日 `¥80.00`、7 月 20 日 `¥20.00`。收入页只显示这两笔且本月收入为 `¥100.00`；切回“支出”后仍只显示支出。两种类型返回的月度汇总都应同时满足收入 `¥100.00`、支出 `¥44.30`、结余 `¥55.70`，分页游标不得跨类型复用。

## 3. 场景二：月份切换与边界

1. 创建一笔上月支出，确认当前月不显示。
2. 切换到上月，确认该记录出现且月度总额只包含上月数据。
3. 来回切换月份，确认列表、日期组、游标和汇总均无残留。
4. 在开发环境验证月初 `00:00:00` 的记录属于当月、下月月初 `00:00:00` 不属于上月；月份归属按当前 `user_settings.timezone`，默认 `Asia/Shanghai`。
5. 当前月的“下一月”按钮应禁用，年月选择器不能选择未来月份。

## 4. 场景三：分页与稳定排序

1. 在同一月份准备至少 21 笔未删除支出，至少两笔使用完全相同的 `occurredAt`，并让同一天的数据跨越第 20/21 条边界。
2. 首次进入只应取得最多 20 条；CloudBase 日志中的列表请求应携带 `cursor=null`。
3. 上拉后加载第二页，确认无重复、无遗漏，相同时间按交易 `_id` 倒序稳定排列，同一天仍只有一个日期标题。
4. 加载完成后显示“没有更多了”，继续滚动不得重复请求。
5. 月度总额必须包含 21 笔以上全部支出，而不是第一页 20 笔的合计。

## 5. 场景四：下拉刷新和新增返回

1. 流水已有数据时下拉刷新，确认列表被第一页新结果替换、汇总重算且没有重复记录。
2. 从流水页进入“新增支出”，保存一笔当前月记录，点击“返回账单流水”；确认只触发一次刷新，新记录出现在正确日期，日小计与月总额更新。
3. 新增一笔历史月份记录并返回；页面应切换到该交易所属月份并加载该月，而不是把记录错误插入原月份。
4. 新增失败时返回不得触发流水刷新。

## 6. 场景五：空、错误和弱网

1. 选择无支出的历史月份，应显示真实 `¥0.00`、空状态和可用的“新增支出”入口。
2. 在首次加载前断网，应显示整页错误和重试按钮，不得显示空月份或 `¥0.00`。
3. 已有数据时模拟刷新失败，原列表和原汇总必须保留，并显示轻提示/重试入口。
4. 模拟第二页失败，第一页必须保留；点击“重新加载”后从原游标继续，不得清空或重复。
5. 快速切换两个月份，旧请求返回后不得覆盖当前选中月份。

## 7. 场景六：多用户隔离

1. 使用两个微信测试账号分别创建同月支出。
2. 用户 A 只能看到 A 的记录与汇总，用户 B 只能看到 B 的记录与汇总。
3. 在 CloudBase 日志中确认列表、聚合、分类和账户关联均包含由真实调用上下文解析出的当前 `ownerId`。
4. 构造含 `ownerId`、`userId` 或任意 `openId` 的请求应返回 `INVALID_ARGUMENT`；客户端直接读取集合应被权限拒绝。
5. 页面响应和日志不得展示完整 `OPENID`、数据库查询表达式、环境凭证或其他用户数据。

## 8. 结果记录

## 9. 独立月度汇总与首页摘要

1. 重新上传部署 `cloudfunctions/ledger` 并重新编译小程序；本任务不新增集合、权限、索引或环境变量。
2. 使用当前账号进入首页，确认显示当前用户时区下的月份、本月收入、本月支出和结余；结余必须等于收入减支出。
3. 分别从首页新增收入和支出，返回首页后确认 `onShow` 重新请求 `getMonthlySummary`，三个金额与记账流水页一致。
4. 删除或跨月编辑一笔账单后返回首页，确认已删除记录被排除、跨月记录只影响对应月份。
5. 使用没有账单的测试账号确认显示 `¥0.00` 和 empty 状态；断网或聚合失败显示 error/retry，不能把错误伪装成零数据。
6. 检查请求 payload 只含 `year`、`month` 和统一信封字段；不得出现客户端提供的身份字段。首页不得直接访问数据库。

以上新增能力尚未在真实 CloudBase 环境执行，本地自动测试通过不能标记为人工验收成功。
